# 시공노트

문자·사진·문서·녹음에서 현장 업무를 기록하고, 중요한 판단과 문서 준비를 돕습니다.

- [업무 화면](https://sigongnote-api.onrender.com/)
- [Windows 설치 파일 다운로드](https://sigongnote-api.onrender.com/download/windows) — 내려받은 `Sigongnote-Setup.exe`를 실행합니다.
- [Android 설치·전체 설치 안내](https://sigongnote-api.onrender.com/install)
- [사용 대시보드](https://sigongnote-api.onrender.com/activity)
- [이 PC의 변경·피드백 창구](http://127.0.0.1:5188/) — PC와 확인 서버가 켜져 있을 때 사용합니다. 결과를 복사해 작업 대화에 전달합니다.

## 사용 흐름

Windows 설치 앱은 로그인 없이 **오늘**을 엽니다. 문서·바탕화면·다운로드와 기존 연결 폴더에서 새 자료를 발견하면 PC에서 읽고, 접수일 원장과 현장별 다섯 분류에 기록합니다. 기존 자료는 먼저 이름·위치만 목록으로 만들고 **기존 자료 정리**에서 필요한 판독을 시작합니다. 원본은 이동하거나 바꾸지 않습니다.

Windows는 설치 파일 하나로 로컬 처리기까지 설치합니다. 검색과 **자료 추가**, **사진대지 만들기**를 바로 사용할 수 있습니다. 정리 결과는 PC의 시공노트 데이터 폴더에 날짜별·현장별 원본 바로가기와 사진대지 PDF로 남습니다. 기본 수집·판독·분류에는 서버 업로드나 AI API 호출이 필요하지 않습니다.

새 문자·자료가 서버에 들어오면 Claude(기본 `claude-sonnet-5`)가 기존 통화·일지·열린 업무를 찾아 생략된 맥락을 복원하고, 업무 사건과 **오늘 할 일**로 남깁니다. 대상 현장을 찾지 못하면 "현장 미특정"으로 남기고 현장을 만들어내지 않습니다. 금액·입금·납품 완료는 AI가 확정하지 않습니다.

웹·휴대폰 자료는 네이버 로그인 후 사용합니다. Windows의 **같은 계정으로 연결**을 사용하면 원장 항목·분류 결과를 공유하고 휴대폰의 현장 수정도 PC에 반영합니다. 서버 보관을 허용한 업무·사진·녹음 폴더는 기존 수집기와 업로더로 원본을 보냅니다. 자동으로 발견하기만 한 일반 파일은 PC에 보관합니다. 휴대폰 촬영은 사진을 찍고 기존 현장을 골라 저장합니다.

연결한 PC에서도 같은 **오늘·현장·문서**를 사용합니다. **업무 기록**에서 원문과 선행 근거를 열고, 잘못 연결된 현장이나 내용을 수정할 수 있습니다. 자료가 바뀌면 최신 판을 다시 해석하며 이전 사건과 할 일은 이력으로 남깁니다. 외부 AI 처리는 회사별 허용 상태를 따르고 설정에서 철회할 수 있습니다.

| 메뉴 | 하는 일 |
|---|---|
| 오늘 | 할 일·검토할 초안 확인, 글·말로 기록하거나 요청 |
| 현장 | 현장별 업무와 자료 확인 |
| 촬영 | 휴대폰 기본 카메라 호출, 현장 사진 모음으로 연결 |
| 문서 | 초안·발행본·받은 자료, 문서 만들기·사진대지 |
| 설정 | 자료 연결·글자 크기 |

자료 본문은 **업무일지에서 해당 기록을 눌러** 봅니다. 웹·휴대폰에서 저장한 자료는 서버에 보관하고, Windows 로컬 자료는 PC에 보관합니다. 삼성 기본 문자앱과 원본 파일은 유지합니다.

문서는 견적서·발주서·일반 청구서·거래명세서 PDF/XLSX와 사진대지를 지원합니다. 새 양식의 사업자 정보·직인 칸·거래 조건은 초안에서 확인합니다. 실제 직인·송금·법정 전자계산서 발행을 자동으로 완료하지 않습니다.

견적은 새 현장이나 PC에서 읽은 자료로도 시작합니다. 품목·수량·매입단가와 마진·부가세를 확인하면 서버가 금액을 계산합니다. 작성 중인 초안은 문서 목록에서 다시 열 수 있고, 발행본은 당시 근거의 해시와 판을 보존합니다. 관리자는 **설정 → 더 보기 → 업무 처리·사용 기록**에서 사건·근거·호출·비용·교정 기록을 확인하고 JSONL로 내려받을 수 있습니다.

운영 버전, 새 설치물, 실제 기기에서 확인한 범위는 **[현재 상태](docs/EXECUTION_STATE.md)**가 정본입니다. 코드 시험·합성 미리보기·실제 연결·사용자 인수를 구분합니다.

Node/npm 버전은 `package.json`, 설치 버전은 lockfile을 따릅니다. Windows에서는 PowerShell7과 `npm.cmd`를 사용합니다.

```powershell
git config core.hooksPath .githooks
npm.cmd ci
node scripts/check-spec.mjs
npm.cmd run typecheck
```

로컬 API·worker·웹 실행과 기기 빌드는 [환경 절차](docs/ENVIRONMENT.md)를 따릅니다. 내부 화면 점검은 `node scripts/ui-shots.mjs --script scripts/ui-flows.json`이며 운영 데이터를 사용하지 않습니다. 문서 인계 ZIP은 `pwsh -NoProfile -File scripts/package-handoff.ps1`로 만듭니다.

과거 실행·검수·복원 기록은 비공개 `.work`와 Git 이력에 보존합니다. 오래된 배포 상태를 README에 중복 기록하지 않습니다.
