# 재개 브리핑 — `$ARGUMENTS`

## 자동 수집(저장소 사실)
- 브랜치: !`git branch --show-current`
- HEAD: !`git log -1 --oneline`
- 미커밋 변경:
!`git status --short`
- 최근 커밋:
!`git log -5 --oneline`

## 순서
1. `docs/EXECUTION_STATE.md`를 Read 한다(50줄 이하, 전체). 다른 문서는 아직 열지 않는다.
2. 현재 카드를 정한다: `$ARGUMENTS`가 있으면 그 카드, 없으면 EXECUTION_STATE의 `현재 작업`·`보완 단위`·`다음 실행` 줄에서 고른다. 고를 수 없으면 사용자에게 한 줄로 묻는다.
3. `docs/AGENT_SPEC.md`(약 500줄)는 전체를 Read 하지 않는다. Grep으로 카드 ID(예 `N31p`)와 그 행이 가리키는 계약 절(D·E·F·I)을 찾아 그 구간만 Read 한다. 넓은 탐색이 필요하면 내장 Explore 서브에이전트에 "해당 카드의 행·의존 카드·관련 계약 줄 번호만 돌려달라"고 맡겨 본 컨텍스트를 아낀다.
4. 미커밋 변경이 있으면 누구의 것인지 구분한다. 사용자 미커밋 자료(루트 개인 MD, `.codex/`, 사용자 시험 파일)는 입력·stage 대상이 아니다. `0.2 ver/`·`.env*`·무관한 `.work` 파일은 열지 않는다(훅이 막는다; 우회하지 않는다).
5. 실행·연결 문제가 보일 때만 `docs/ENVIRONMENT.md`의 해당 절만 읽는다.
6. 사용자 승인·결제·OS 권한이 필요한 항목(H02~H10)은 게이트로 분리해 한 줄로 알리고, 독립 작업을 고른다.

## 출력(10줄 안, 한국어)
1) 현재 기준 SHA/브랜치 2) 단계와 현재 카드·목표 사용자 행동 3) 의존 카드와 공개 계약 위치(파일:줄) 4) 소유 파일 후보 5) 필수 회귀(돈/DB/계약/UI 중 해당) 6) 미검증·잔여 실제 연결 7) 대기 중 H게이트(있으면) 8) 미커밋 변경의 처리 방침 9) 첫 행동 하나 10) "진행할까요?" — 사용자 답 전에는 파일을 바꾸지 않는다. 구현은 `/ncard <카드>`로 이어간다.
